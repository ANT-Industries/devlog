CasaOS SSH Connection Failed

by @Tyler-Alcorn

Encountered an error while trying to connect to CasaOS via SSH. The connection was failing with a handshake error indicating no supported authentication methods remain.

{
  "error": "ssh: handshake failed: ssh: unable to authenticate, attempted methods [none password], no supported methods remain",
  "func": "v1.PostSshLogin",
  "file": "/home/runner/work/CasaOS/CasaOS/route/v1/ssh.go", 
  "line": 41
}

1. Host Key Verification Failed

After attempting to SSH directly (ssh root@192.168.0.150), we hit a WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED! error. This was likely due to a re-installation of the OS on the same IP.

Fix: Removed the old key from known_hosts:

ssh-keygen -R 192.168.0.150

2. Permission Denied (Forgot Password)

Once the host key was accepted, we couldn't log in due to a lost or unset root password (Permission denied).

Fix:

  1. Opened the Proxmox Console for the VM.
  2. Verified the user existed (grep -E 'sh$' /etc/passwd).
  3. Reset the root password: 
    passwd root
  4. Ensured root login was allowed in /etc/ssh/sshd_config (PermitRootLogin yes) and restarted SSH.

Successful connection established!

Mounting UNAS via Proxmox Bind Mount (LXC)

by @Tyler-Alcorn

We attempted to mount the UNAS NFS share directly inside the CasaOS LXC container, but hit repeated Operation not permitted errors. This is a common security restriction in unprivileged containers, even with the "NFS" feature flag enabled.

The Solution: Host-Passthrough (Bind Mount) Instead of mounting inside the container, we mounted it on the Proxmox Host and passed the folder through.

1. Mount on Proxmox Host

In the Proxmox Node Shell:

# Create mount point
mkdir -p /mnt/pve/unas

# Mount NFS share
mount -t nfs 192.168.0.23:/var/nfs/shared/server /mnt/pve/unas

2. Pass to Container (Bind Mount)

Still in the Host Shell, we used pct set to map the host directory to the container directory:

# Syntax: pct set <VMID> -mp0 /host/path,mp=/container/path
pct set 150 -mp0 /mnt/pve/unas,mp=/mnt/unas

3. Result

The files immediately appeared in CasaOS at /mnt/unas without needing to fiddle with container privileges or AppArmor profiles.
